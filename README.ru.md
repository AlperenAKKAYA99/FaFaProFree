## 🔬 Цели образовательного исследования

Данный проект исследует ключевые концепции современной программной инженерии:

1. **Интернационализация терминала (i18n):** Модульная система словарей JSON (`lang/*.json`) с поддержкой иерархических запасных вариантов (fallback) и форматирования с точечной нотацией.
2. **Отказоустойчивый парсер релизов:** 4-уровневый алгоритм обнаружения версий через REST API GitHub, HTML-пагинацию (`releases?page=N`) и Atom-ленты (`releases.atom`) без ограничений по квотам запросов.
3. **Возобновление загрузки HTTP Range:** Устойчивая докачка байтов при сетевых сбоях через заголовок `Range: bytes={pos}-`.
4. **Потоковая криптографическая проверка:** Потоковое чтение блоками по 1 МБ с расчетом контрольных сумм `hashlib.sha256()` без перегрузки оперативной памяти.
5. **Атомарная изоляция сборок (Atomic Staging):** Промежуточная сборка в `build/.staging/` гарантирует отсутствие поврежденных файлов при аварийном завершении (`CTRL+C`).
6. **Кросс-сборочное переиспользование:** Автоматическое обнаружение уже проверенных локальных ресурсов, исключающее повторную загрузку и экономящее 90–100% трафика.

## 📖 Руководство по использованию

### 1. Интерактивный мастер (Wizard)

Запустите скрипт без параметров для пошагового управления:

```bash
python fa_pro_v3.py
```

Мастер последовательно запрашивает:
1. **Язык:** `[1] English`, `[2] Türkçe`, `[3] Русский`, `[4] Deutsch`
2. **Профиль:** `[1] Free`, `[2] Pro`, `[3] Pro-Plus`, `[4] Custom`
3. **Версию:** Обнаруженные релизы в реальном времени (например: v7.3.1, v7.3.0, v6.7.2 LTS) или полный список версий
4. **Категории:** `[1] Стандартный веб-пакет`, `[2] Расширенный (+Sprites)`, `[3] Выборочный`

---

### 2. Многоязычный интерфейс (`--lang`)

Переключайте язык консольного вывода на лету:

```bash
# Русский язык
python fa_pro_v3.py --lang ru --list-versions

# Английский язык
python fa_pro_v3.py --lang en --list-versions

# Турецкий язык
python fa_pro_v3.py --lang tr --list-versions

# Немецкий язык
python fa_pro_v3.py --lang de --list-versions
```

---

### 3. Поиск релизов в реальном времени (`--list-versions`)

Динамическое сканирование `https://github.com/FortAwesome/Font-Awesome/releases?page=*` с кэшированием и проверкой доступности CDN:

```bash
# Вывести список всех найденных версий, сгруппированных по мажорным релизам (v7, v6, v5)
python fa_pro_v3.py --list-versions

# Принудительно обновить кэш из GitHub и проверить CDN
python fa_pro_v3.py --refresh-versions --list-versions --validate-cdn

# Сканировать глубже по страницам (по умолчанию: 3 страницы)
python fa_pro_v3.py --list-versions --pages 5
```

---

### 4. Командная строка (CLI)

Для скриптов автоматизации и конвейеров CI/CD:

```bash
# Сборка профиля Pro (CSS + Webfonts) без диалогов
python fa_pro_v3.py --version 7.3.1 --profile Pro --css --fonts --non-interactive

# Сборка полного профиля Pro-Plus
python fa_pro_v3.py --version 7.3.1 --profile Pro-Plus --non-interactive

# Сборка официального бесплатного пакета Free
python fa_pro_v3.py --version 7.3.1 --profile Free --non-interactive

# Упаковать результат в zip-архив
python fa_pro_v3.py --version 7.3.1 --profile Pro --archive --non-interactive
```

---

### 5. Симуляция сборки (`--dry-run`)

Оценка плана загрузок без фактического скачивания файлов:

```bash
python fa_pro_v3.py --version 7.3.1 --profile Pro --dry-run
```

Пример вывода:
```text
  ✓ css/all.css                            → Повторное использование (кэш/сборка)
  ✓ js/all.js                              → Повторное использование (кэш/сборка)
  ↓ webfonts/fa-solid-900.woff2            → Загрузка
  План: 0 пропущено, 62 повторно использовано, 1 загружается
```

---

### 6. Проверка целостности (`--verify`)

Проверка криптографических хэшей SHA-256 без загрузки:

```bash
python fa_pro_v3.py --version 7.3.1 --profile Pro --verify
```

---

### 7. Восстановление поврежденных файлов (`--repair`)

Сканирование каталога и выборочная загрузка только поврежденных или отсутствующих файлов:

```bash
python fa_pro_v3.py --version 7.3.1 --profile Pro --repair
```

## ⚡ Интеллектуальный механизм решений и целостность данных

```text
                 ┌──────────────────┐
                 │  Файл найден на  │
                 │      диске?      │
                 └────────┬─────────┘
                          │
                ┌─────────▼─────────┐
                │        ДА         │
                └─────────┬─────────┘
                          │
                 Проверка SHA-256
                          │
             ┌────────────┴────────────┐
             │                         │
         СОВПАДАЕТ                РАЗЛИЧАЕТСЯ
             │                         │
             ▼                         ▼
      ПРОПУСТИТЬ ФАЙЛ         ПОВТОРНАЯ ЗАГРУЗКА
     (Экономия трафика)     (Поврежденный файл)
```

1. **Контроль хэшей SHA-256:** Файлы не считаются корректными только по имени или размеру; хэш каждого файла сверяется с манифестом.
2. **Кросс-сборочное повторное использование:** 63 общих файла из `v7.3.1-Pro` автоматически копируются при сборке `v7.3.1-Pro-Plus` (экономия более 92% трафика).
3. **Изоляция `.part` файлов:** Скачивание идет во временные `.part` файлы и подтверждается переименованием только после валидации контрольной суммы.

## 🎛️ Профили сборки

Конфигурация описана в [config/build_profiles.json](config/build_profiles.json):

| Профиль | Количество семейств | Описание |
| :--- | :---: | :--- |
| **Free** | 3 | Официальные бесплатные стили: `Solid`, `Regular`, `Brands`. |
| **Pro** | 17 | Classic (`Solid`, `Regular`, `Light`, `Thin`), Duotone, Sharp и Brands. |
| **Pro-Plus** | 37 | Стили Pro + 20 специализированных семейств (`Chisel`, `Etch`, `Jelly`, `Mosaic`, `Pixel` и др.). |
| **Custom** | Выборочно | Произвольный набор стилей, заданный разработчиком. |

## 📁 Архитектура изолированного каталога сборки

Каждая сборка изолирована в отдельном каталоге:

```text
build/
└── v7.3.1-Pro-Plus/
    ├── css/
    ├── js/
    ├── webfonts/
    ├── LICENSE.txt          # Уведомления сторонних авторов и лицензии
    ├── BUILD_INFO.json      # Метаданные версии, профиля и времени
    ├── BUILD_REPORT.json    # Аудит и отчет проверки целостности
    └── manifest.json        # Список файлов, размеры и хэши SHA-256
```

## ⚙️ Интеграция с GitHub Actions CI/CD

В репозитории настроены 2 автоматических рабочих процесса:
1. **`.github/workflows/build.yml`:** Автоматическое тестирование целостности и сборки при коммитах и pull request'ах.
2. **`.github/workflows/release.yml`:** Автоматическая упаковка zip-архивов и публикация в GitHub Releases при создании тэга (`v*`).
